# Governance

The project is currently maintained by its founding maintainer. Decisions are
recorded transparently in issues, pull requests, and architecture decision
records.

## Decision process

- Implementation details are decided through normal pull-request review.
- Wire-protocol, trust-boundary, license, and compatibility changes require an
  Architecture Decision Record before merge.
- Breaking protocol changes require a new major protocol version and migration
  notes.
- Security fixes may be prepared privately and documented after release.

## Maintainer responsibilities

Maintainers review code and provenance, protect release credentials, publish
signed artifacts and SBOMs, and avoid accepting features that weaken the stated
trust boundaries without an explicit design decision.

The governance model may evolve as additional long-term maintainers join.
